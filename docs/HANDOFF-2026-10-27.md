## The owner's goals

1. **Same output.** For the same design, PE-DESIGN's stitches and OpenStitch's are as close as
   possible. Measured per design with `tools/pescmp.py` (needle-to-nearest-needle distance, area
   overlap, stitch counts) and pinned by the compat specs.
2. **Editable round trip.** A PES saved by PE-DESIGN opens in OpenStitch with its shapes, text
   and attributes editable, and the other way round, with no feature loss. PE-DESIGN keeps
   editable objects only in `#PES0110`; its Ver. 6.0 save turns them into stitches.
3. **Same on the machine.** An OpenStitch export sews on a Brother machine as PE-DESIGN's export
   of the same design would. Measured on the PEC stitch stream with `tools/peccmp.py`; the final
   proof is a sew-out record under `compat/machine/`.

Plus: after each release, a full docs review (add, update, remove stale).

## Where the comparison stands

`tools/pescmp.py <ours.pes> <theirs.pes>` compares two PES files of the same design.
On the final `main`, 102 spec designs have both an OpenStitch export and a PE-DESIGN 11.50 file. 32 of them match PE-DESIGN needle point for needle point with the same stitch count (rectangles and squares at 0° and 90° across the density, pitch, Frequency and pull sweeps; the satin rectangle and column; stem, candlewick and chain lines; the Feed/Run files; PE-DESIGN's re-saves of OpenStitch files). The median area overlap is 0.92 and the median needle-to-nearest-needle distance 0.16 mm. The largest remaining gaps, by overlap:

| Spec | Overlap | Mean distance | Stitches (OpenStitch / PE-DESIGN) |
|---|---|---|---|
| `region-travel-u-gradation` | 0.56 | 0.32 mm | 587 / 619 |
| `text-fit-default` | 0.67 | 0.27 mm | 932 / 854 |
| `text-fit-halign-spaced` | 0.67 | 0.24 mm | 938 / 862 |
| `text-fit-orient-upright` | 0.67 | 0.23 mm | 873 / 850 |
| `text-fit-valign-center` | 0.69 | 0.23 mm | 932 / 854 |

The gradation U is a routing difference (PE-DESIGN sews the right leg first); the text-fit specs and the 60° bend are the text-fill and corner gaps named in the track notes. `tools/peccmp.py` diffs the PEC stream record by record; see [research/2026-10-27/machine-equiv.md](research/2026-10-27/machine-equiv.md).

## How the day was run (keep this)

- **One PR per coherent change, each landing its fix together with the PE-DESIGN reference file and
  its MANIFEST entry, so `main` stays green.** CI's compat step fails if any spec fails.
- **Merge queue.** `docs/COMPATIBILITY_STATUS.md`, `compat/reference/MANIFEST.json`,
  `docs/COMPATIBILITY_TESTS.md` and the badge goldens conflict on every merge, so PRs that touch
  them land one at a time, in a published order, and a PR rebases only when it reaches the head.
  PRs that touch none of those files merge as soon as they are green.
- **When PE-DESIGN's observed behaviour contradicts a spec's own expected value, the observation
  wins**: the expected value changes to what PE-DESIGN does, citing the reference file, and the
  matching audit item is corrected in the same PR. A measurement may be fixed only when it
  mismeasures, with a unit test on a synthetic input, and it must apply equally to both sides.
- **PE-DESIGN is used black-box only**: its UI and the files it saves. Never its program files.
  Studying the owner's own output files is allowed as project policy (#60,
  [LEGAL_AND_LICENSING.md](LEGAL_AND_LICENSING.md)).
- **Manifest notes are public**: no local paths, user or machine names (rule in
  `compat/reference/README.md`, enforced by review; #65 redacts the ones that slipped in).
- **No compiled helpers on the owner's machine** (PowerShell `Add-Type` and the like): the
  antivirus flagged one. Use the app's own tools or built-ins.
- **Fonts for text references:** Lato Bold (OFL, bundled with OpenStitch) is installed for the
  owner's Windows user so PE-DESIGN and OpenStitch use the same font. PE-DESIGN stores text as
  letters plus a font name, no outlines, so a text round-trips only when both programs have the font.
